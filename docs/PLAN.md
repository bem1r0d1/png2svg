# png2svg — архитектура и план разработки

Цель: конвертер растра (PNG/JPG/WebP) в SVG, который даёт **чистые, редактируемые векторы без артефактов** (лесенки, «бахромы» на антиалиасинге, щелей между фигурами, мусорных точек) и **заточен под Figma**: работает как плагин, принимает картинку прямо из выделения и возвращает аккуратные слои, привязанные к стилям/переменным файла.

---

| 3–8 | впереди |

Текущие метрики по корпусу (`cargo run --release -p png2svg-metrics --bin bench`): средний SSIM ≈ 0.983, средний ΔE ≈ 0.45; логотипы и шрифтовые глифы — SSIM 0.9997–0.9999.

Деградированные входы (пикселизация, ступеньки без сглаживания, шум, JPEG, размытие) сравниваются не с собой, а с чистым эталоном (`*.ref.png`): метрика показывает, насколько дефект *убран*, а не скопирован.

Известные слабые места (этап 3): линии толщиной ~1 px слегка волнистые — нужен режим осевых линий (stroke); кончики острых углов на сильно сжатом JPEG притупляются — поможет регуляризация симметрии; очень мелкие иконки (24 px) теряют часть углов.

## Что взято у Vectorizer.AI

Сайт и API-документация Vectorizer.AI изучены по опциям API (`processing.*`, `output.*`) и описаниям движка. Что они делают и как это перенесено к нам:

| Vectorizer.AI | Суть | У нас |
|---|---|---|
| Deep Vector Engine: «субпиксельная точность», границы по значениям антиалиасинга | граница ставится по доле покрытия AA-пикселя | ✅ было с этапа 1 (модель смешивания + marching squares) |
| `processing.parameterized_shapes.*` (circle, ellipse, rectangle, quadrilateral, triangle, star N3–N6, bullet) | целые контуры заменяются точными примитивами | ✅ круг, эллипс (в т.ч. повёрнутый), прямоугольник, скруглённый прямоугольник, «пилюля»; осевые — родными `<circle>/<ellipse>/<rect>` → в Figma это Ellipse/Rectangle с редактируемым радиусом. ⏳ звёзды, треугольники, правильные многоугольники — через регуляризацию симметрии |
| `output.parameterized_shapes.flatten` | выводить примитивы кривыми | ✅ `flattenShapes` |
| «Clean corners», восстановление прямых даже при размытии | углы в точке пересечения сторон | ✅ регуляризация: стороны подгоняются прямыми по внутренним точкам, угол — их пересечение; угол ищется на двух масштабах |
| `processing.palette` + `max_colors` | шаблон палитры, привязка цветов с допуском | ✅ `palette` + `paletteTolerance` (ΔE); плагин подставляет цвета стилей и переменных документа |
| `processing.shapes.min_area_px` | порог минимальной площади | ✅ `speckleArea`, ползунок «Мин. площадь» |
| `output.group_by` (none / color / parent / layer) | структура слоёв | ✅ `groupBy: shape` (фигура = контур + её дырки, сгруппированы по цвету) и `color` |
| `output.shape_stacking` (cutouts / stacked) + `output.gap_filler` | стыковка встык и обводка-заплатка против белых щелей | ✅ stacked с субпиксельным подлогом — щелей нет без заплаток (в Figma заплатки-обводки мешали бы редактированию). ⏳ cutouts как опция |
| `output.curves.allowed.*` (quadratic, cubic, circular/elliptical arcs), `line_fit_tolerance` | набор допустимых кривых, допуск | ✅ кубические Безье + отрезки, допуск = «Гладкость». Дуги не нужны: Figma всё равно хранит Безье |
| Симметрия (зеркальная и вращательная) | «математически симметричный результат» | ⏳ этап 6: поиск осей симметрии и усреднение симметричных контуров |
| `output.draw_style` (fill / stroke shapes / stroke edges) | контуры вместо заливок | ⏳ вместе с режимом осевых линий для line-art |

## 1. Что умеют существующие решения и что берём

| Решение | Как работает | Что берём | Чего избегаем |
|---|---|---|---|
| **Image Tracer** (Figma) | Порог → Potrace, только ч/б | Простой режим «моно» для иконок и line-art | Только один цвет, рваные контуры на шуме |
| **Convertify** (Figma) | Трассировка + настройки, рекомендует апскейл перед трассировкой | **Апскейл маленьких картинок до трассировки** | Ручной подбор параметров |
| **ToSVG** (Figma) | AI-векторизация + удаление фона | **Удаление фона** как шаг пайплайна | Закрытый облачный бэкенд |
| **Vectorizer.AI** | Нейросеть + вычислительная геометрия, **фиттинг примитивов** (окружности, эллипсы, скруглённые прямоугольники), общие границы | **Детекция примитивов, общие границы между фигурами, адаптивность** | Платно, облако |
| **VTracer** (visioncortex, MIT) | Иерархическая кластеризация цветов, O(n) фиттинг, режим «stacked» | **Stacked-режим (без щелей), быстрая кластеризация, Rust/WASM** | Слабая обработка антиалиасинга и градиентов |
| **Potrace** (GPL) | Бинарная трассировка, оптимизация кривых | Идеи: определение углов (alphamax), opticurve | GPL — код не копируем, только идеи из статьи |
| **Vector Magic** | Сегментация + уровни детализации, правка результата | Предпросмотр + ручная правка палитры | — |

**Ключевые выводы:**
1. Качество определяется не столько трассировкой, сколько **предобработкой** (антиалиасинг, JPEG-шум, апскейл) и **топологией** (общие границы между цветами).
2. «Пиксели» и «лесенки» появляются, когда контур строится по центрам пикселей. Нужен **субпиксельный контур** по покрытию (coverage) антиалиасинга.
3. Щели между фигурами в Figma появляются, когда соседние фигуры фиттятся независимо. Решение — **общая граница фиттится один раз** либо **stacked-укладка**.
4. Для Figma важны: мало узлов, без `transform`, без `<use>`, без процентных градиентов, понятные имена слоёв, привязка к Color Styles / Variables.

## 2. Общая архитектура

```
┌──────────────────────── Figma ─────────────────────────┐
│  code.ts (main thread, sandbox, без DOM)               │
│   • читает выделение, getBytesAsync() картинки         │
│   • вставляет результат (createNodeFromSvg / vectorPaths)│
│   • привязывает fills к стилям/переменным, именует слои │
│            ▲  postMessage  ▼                            │
│  ui.html (iframe: DOM, Canvas, WASM, Web Worker)        │
│   • UI: пресеты, слайдеры, палитра, превью/дифф         │
│   • worker → png2svg-core.wasm (весь пайплайн)          │
│   • resvg-wasm → рендер SVG обратно для метрик          │
└─────────────────────────────────────────────────────────┘

Тот же core используется в:
  • CLI (нативная сборка) — батч, тесты, бенчмарки
  • Web-демо (опционально)
```

**Почему так:**
- Вся обработка **локально** (WASM в iframe плагина): приватность, оффлайн, без серверных затрат. Облачный «AI-режим» — опционально позже.
- **Rust → WASM** для ядра: скорость (картинки 4K, итеративная подстройка), можно опираться на крейты `visioncortex` (MIT) как референс/зависимость, один код для плагина и CLI.
- Тяжёлые вычисления в **Web Worker**, UI не фризится; отмена задачи при смене параметров.

### Структура монорепозитория

```
png2svg/
├─ crates/
│  ├─ core/          # Rust: пайплайн (анализ → предобработка → квантование →

```

## 3. Пайплайн конвертации (логика)

```
PNG ─► 0.Декод ─► 1.Анализ/классификация ─► 2.Предобработка ─► 3.Палитра
    ─► 4.Сегментация ─► 5.Топология границ ─► 6.Субпиксельные контуры
    ─► 7.Углы + фиттинг Безье ─► 8.Примитивы и снаппинг ─► 9.Градиенты
    ─► 10.Сборка SVG ─► 11.Проверка качества (рендер+сравнение) ─► 12.Импорт в Figma
```

### 0. Декодирование
- Из Figma: `figma.getImageByHash(hash).getBytesAsync()` → в UI декод через `createImageBitmap` → RGBA.
- Учитываем `scaleMode`/`imageTransform` заливки и размер ноды, чтобы итоговый вектор лёг ровно на место картинки.
- Альфа: работаем в **straight alpha** (un-premultiply), иначе на краях появляется тёмная кайма.

### 1. Анализ и автоклассификация
Метрики: число уникальных цветов, гистограмма, доля полупрозрачных пикселей, плотность краёв, наличие плавных переходов, размер, «пиксельность» (кратные блоки одного цвета), JPEG-блочность.

Тип → пресет:
| Тип | Признаки | Стратегия |
|---|---|---|
| **Pixel art** | мало цветов, жёсткие края, блоки N×N | без сглаживания, прямоугольные полигоны (или Kopf–Lischinski как опция) |
| **Иконка / моно** | 1–2 цвета + AA | бинаризация по покрытию, максимальная гладкость |
| **Логотип / flat** | 2–16 цветов, AA на краях | основной режим |
| **Иллюстрация** | 16–64 цвета, градиенты | больше цветов + детекция градиентов |
| **Фото** | тысячи цветов, шум | предупреждение: «вектор будет стилизацией», постеризация |

Пользователь всегда может переключить пресет вручную.

### 2. Предобработка
- **Удаление фона**: если альфы нет и рамка картинки однородного цвета — flood-fill от краёв → прозрачность (опция).
- **Шумоподавление** с сохранением краёв: медиана / bilateral; JPEG-деблокинг для JPG-источников.
- **Апскейл** маленьких изображений (< ~256 px по стороне) в 2–4× (идея из Convertify). Базово — edge-aware интерполяция; опционально ONNX-модель (Real-ESRGAN-lite) через onnxruntime-web.
- Для pixel art — наоборот, **даунскейл до «логического» пикселя** (детекция размера блока).

### 3. Палитра (квантование)
- Работаем в **OKLab** (перцептивно равномерное пространство) — нет «грязных» промежуточных цветов.
- Пиксели с AA (смесь двух цветов) **исключаются из построения палитры** — иначе получаем лишние цвета-бахрому.
- Алгоритм: Wu / k-means++ по взвешенной гистограмме; авто-K по «колену» ошибки; слияние цветов с ΔE < порога.
- **Снаппинг к стилям Figma**: если цвет палитры близок (ΔE < 2) к Color Style / Variable документа — подставляем его точно. Очень полезно для логотипов бренда.
- Палитра редактируема в UI: объединить, удалить, заменить цвет.

### 4. Сегментация
- Каждый пиксель → ближайший цвет палитры, **но AA-пиксели** распределяются между двумя соседними регионами пропорционально покрытию (используется на шаге 6).
- Связные компоненты (8/4-связность — зависит от пресета).
- **Удаление спеклов**: регионы меньше порога площади вливаются в соседа с самой длинной общей границей (а не в ближайший по цвету — так не рвутся тонкие линии).

### 5. Топология: общие границы (главное против щелей)
Строим **планарную карту**: граница между регионами A и B — одна цепочка рёбер, концы — узлы-перекрёстки (3+ регионов или край изображения).

Два режима вывода:
- **Stacked (по умолчанию для Figma)**: фигуры укладываются слоями от фона к деталям; нижний слой «заходит» под верхний (дырки заполнены). Щелей нет в принципе, слои удобно перекрашивать и двигать.
- **Cutout (мозаика)**: фигуры стыкуются встык, но каждая общая граница **фиттится один раз** и используется обеими фигурами (прямо и реверсивно) → совпадение кривых бит-в-бит, без hairline-щелей.

### 6. Субпиксельные контуры (главное против «лесенки»)
- Контур ищется не по границам пикселей, а **marching squares по полю покрытия**: для AA-пикселя доля цвета региона задаёт положение границы внутри пикселя.
- Для бинарной маски без AA — предварительное лёгкое размытие поля, затем изолиния 0.5.
- Результат — полилиния с субпиксельной точностью, уже без ступенек.

### 7. Углы и фиттинг кривых
1. **Детекция углов**: угол между касательными на масштабе k (multi-scale) + кривизна; порог настраивается («Острые углы ↔ Скруглённые»).
2. Разбиение контура в углах на сегменты.
3. **Фиттинг кубических Безье** (алгоритм Schneider, least squares) с допуском ошибки; при превышении — разбиение и рефиттинг.
4. **G1-непрерывность** в гладких стыках (касательные выровнены), в углах — разрыв касательной.
5. Минимизация числа узлов: объединение сегментов, если ошибка позволяет.
6. Прямые участки → `L`, не кривые.

### 8. Примитивы и снаппинг (идея Vectorizer.AI)
- Детекция: отрезок, окружность, эллипс, прямоугольник, скруглённый прямоугольник (RANSAC/least squares по сегменту).
- Если ошибка мала — заменяем на точный примитив (идеальная окружность из 4 Безье).
- **Снаппинг**: почти горизонтальные/вертикальные линии → строго 0°/90°; координаты на сетку 0.01 px (или 0.5 px для иконок); выравнивание касательных у почти совпадающих точек.
- Опционально: детекция симметрии.

### 9. Градиенты
- Регион с плавным изменением цвета (вместо полос постеризации) → аппроксимация **линейным/радиальным** градиентом (регрессия цвета по координатам, 2–4 стопа).
- В SVG только `gradientUnits="userSpaceOnUse"` с абсолютными координатами (Figma некорректно импортирует процентные градиенты). Надёжнее — выставлять `GradientPaint` через Plugin API после импорта.

### 10. Сборка SVG
- `viewBox` = размеры оригинала, без `transform`, без `<use>`, `<style>`, фильтров и масок.
- Один `<path>` на регион (или на цвет — опция «объединить по цвету», меньше слоёв), `fill-rule="evenodd"` для дырок.
- Компактный path data: относительные команды, точность 2 знака, без лишних пробелов.
- Только `fill`, без `stroke` (опция «линии как stroke» для line-art — позже).
- Осмысленные `id` → имена слоёв в Figma (`Color/1A2B3C`, `Background`).

### 11. Контроль качества (авто-подстройка)
- Рендерим SVG обратно (**resvg-wasm**) в том же разрешении и сравниваем с оригиналом: **SSIM**, средний/максимальный **ΔE (OKLab)**, ошибка на краях.
- **Тепловая карта ошибок** в UI поверх превью.
- Авто-режим: зоны с высокой ошибкой → уменьшаем допуск фиттинга / добавляем цвет локально, 1–3 итерации.
- Учитываем сложность: число узлов/точек — штраф (Figma тормозит на тысячах слоёв).

### 12. Импорт в Figma
- Основной путь: `figma.createNodeFromSvg(svg)` → Frame с векторами.
- Пост-обработка через API:
  - позиция/размер = исходная нода картинки (с учётом поворота/трансформа);
  - имена слоёв, группировка по цветам;
  - привязка fills к **Color Styles / Variables** (из шага 3);
  - градиенты — через `GradientPaint`;
  - опции: «Заменить картинку» / «Вставить рядом» / «Оставить оригинал скрытым под вектором»;
  - опция Flatten (один вектор) или Union по цвету.
- Ограничение сложности: предупреждение при > N путей/точек.

## 4. UI плагина

- **Пресеты**: Auto · Logo · Icon · Illustration · Pixel art · Line art.
- **Слайдеры**: Цвета (авто/число), Детализация, Гладкость, Острота углов, Порог спеклов.
- **Переключатели**: Удалить фон · Апскейл · Stacked/Cutout · Примитивы · Градиенты · Снап к стилям.
- **Палитра**: чипы цветов, клик — объединить/удалить/заменить на стиль.
- **Превью**: сравнение со шторкой (оригинал | вектор), зум до пикселя, режим «каркас» (узлы), тепловая карта ошибок; счётчики: слои, узлы, SSIM.
- Живое обновление с debounce, отмена устаревших задач в воркере.
- Пакетная обработка нескольких выделенных картинок.

Технологии UI: Preact + TypeScript, Vite + `vite-plugin-singlefile` (Figma требует один HTML), WASM инлайнится base64 или грузится как data-URL.

## 5. API ядра (WASM)

```ts
interface ConvertOptions {
  preset: 'auto' | 'logo' | 'icon' | 'illustration' | 'pixel' | 'lineart';
  colors?: number | 'auto';
  detail: number;          // 0..1 → допуск фиттинга, порог спеклов
  smoothness: number;      // 0..1
  cornerThreshold: number; // градусы
  layering: 'stacked' | 'cutout';
  removeBackground: boolean;
  upscale: 'auto' | 1 | 2 | 4;
  detectPrimitives: boolean;
  detectGradients: boolean;
  paletteLock?: RGBA[];    // цвета из стилей Figma для снаппинга
}

interface ConvertResult {
  svg: string;
  layers: { id: string; color: RGBA | Gradient; area: number; pathCount: number }[];
  palette: RGBA[];
  metrics: { ssim: number; meanDeltaE: number; nodes: number; ms: number };
  detectedType: string;
}

convert(rgba: Uint8Array, w: number, h: number, opts: ConvertOptions): ConvertResult
```

## 6. Тестирование и метрики

- **Корпус**: ~100 картинок по категориям — логотипы, иконки (16–512 px), текст с AA, pixel art, иллюстрации с градиентами, JPEG с артефактами, полупрозрачность.
- **Регрессия в CI**: для каждой картинки SSIM / ΔE / число узлов не хуже порогов; отчёт HTML с превью было/стало.
- **Unit-тесты**: фиттинг Безье, детекция углов, примитивы, топология (общая граница A|B идентична в обеих фигурах).
- **Figma-совместимость**: валидатор SVG на разрешённое подмножество; ручной smoke-тест импорта перед релизом.
- **Бенчмарки**: время на 512² / 2048² / 4096², память воркера.
- Сравнение с VTracer / Potrace на том же корпусе — как baseline.

## 9. Критерии «без артефактов» (Definition of Done)

1. Нет щелей между соседними фигурами при любом зуме в Figma.
2. Нет ступенек: на диагоналях и окружностях контур гладкий (проверка кривизны).
3. Нет бахромы: число цветов не растёт из-за AA-пикселей.
4. Нет мусора: нет фигур площадью < порога.
5. Прямые — прямые, окружности — окружности (для логотипов/иконок).
6. SSIM ≥ 0.97 и средний ΔE ≤ 2 на корпусе логотипов/иконок.
7. Вектор встаёт ровно на место исходной картинки, слои названы, цвета привязаны к стилям.
